# Guía de trabajo

1. Crear rama desde develop para una tarea concreta.
2. Leer WORKSPACE.md, alcance y criterio de aceptación.
3. Explicar propósito y flujo; implementar solo la entrega acordada.
4. Probar comportamiento, datos inválidos y permisos según riesgo.
5. Guardar evidencia, actualizar backlog y CHANGELOG.
6. Revisar diff, crear commit descriptivo y preparar pull request.

Tipos de commit: feat, fix, docs, test, refactor, chore.

Terminado significa código ejecutado, errores previsibles controlados, prueba o evidencia reproducible y documentación actualizada. Un diseño o pantalla aislada no demuestra una entrega integrada.

No versionar .env real, contraseñas, dependencias ni cachés. SQL candidato es documentación; migraciones son esquema ejecutable. No hacer push ni publicar sin instrucción del usuario.
